# uPD7810/7811 core

`hdl/upd7810/`: the CPU of the CZ-101 (a uPD7811 at 10 MHz). It follows MAME's `upd7810`
device (BSD-3-Clause, Juergen Buchmueller) instruction for instruction: registers, flags,
skips, memory writes in order, cycle counts, peripheral state and interrupt entries.

| File | What |
|---|---|
| `upd7810_core.sv` | Fetch, decode, execute; interrupt entry; cycle debt paid by `cyc_ce` |
| `upd7810_decode.hex/.txt` | Decode ROM, generated by `tools/upd7810_gen.py` from MAME's `upd7810_table.cpp` |
| `upd7810_periph.sv` | Ports, timers 0/1, timer F/F, event counter, serial port, A/D, IRR and priority |
| `upd7811.sv` | Core + peripherals + 4 KB internal ROM + 256 B internal RAM |

## Timing model (MAME `execute_run`)

1. Fetch and decode. If SK is set (and the opcode is not SOFTI), step over the instruction
   with its skip cycle count.
2. `handle_timers(main-table cycles)`. For a prefixed opcode (48, 4C, 4D, 60, 64, 70, 74) the
   main-table count is 0 and `PRE_xx` calls `handle_timers(prefix-table cycles)` a second
   time. The A/D converter acts once per call, so the two calls are kept separate.
3. Execute. Interrupt entry takes no cycles.
4. Take an interrupt, then `IFF = iff_pending` (not in the halt loop).

`handle_timers(n)`: each counter adds `n` and drains with a `while` loop. The HDL adds one
cycle to every running counter, then drains pending ticks one per clock (timer 0, timer 1,
event counter, serial), so a backlog left by a divider change drains as MAME's loops do.
Serial mode 0 (clocked by TO) only advances when TO changes, as MAME's `update_sio(1)`.

## MAME behaviour kept on purpose

- `ADCX_*` pass carry 0 to `ZHC_ADD` (ADC, ADCW and ACI pass CY): decode ALU op 16.
- GT compares use a 16-bit temporary (32-bit for DGT): carry and zero follow from that.
- EOM reads are masked with 0x22; MOV MA/MB/MC/MCC/MF with an unchanged value do nothing.
- MVI A / MVI L / LXI H skip their operands when L1/L0 is set.
- Timer 0/1, F1/F2, E0/E1, EIN/AD, SR/ST share vectors; IRR is cleared on entry only when the
  other source of the pair is masked.
- Serial format tables, including the 0xFC transmit word with one stop bit set.
- In `cz101`, MAME maps the internal ROM over 0000-0FFF in front of the program ROM.

Known MAME flag bugs these copy (found 2026-11-23 by the P2K session; not fixed in our MAME
base 4a92d534):
- `ADCX_*` with carry 0: differs from ADC only for operand 0xFF with CY = 1 (CY stays clear,
  should be set). A fix is on branch `upd7810-adcx-carry` of gmcnaught/mame, not submitted.
  If the base takes it, A_ADCX becomes A_ADC.
- `ZHC_ADD` / `ZHC_SUB` compute HC wrongly with a carry/borrow in and an operand low nibble of
  0xF (4,096 cases each): ADC, ACI, ADCX, ADCW, SBB, SBI, SBBX, SBBW, and DAA after them.
  Unfixed anywhere. A change in the base means changing the HDL and re-running C1/C2.

## Checks

`tools/c1_run.sh SEED [N] [--sfr]`: a random program (`tools/upd7810_randprog.py`) runs on
the patched MAME (`mame/patches/0001-cz101-logging.patch`, `CZ_TRACE`) and on
`out/sim/upd7811_bench`; the traces must be identical up to instruction N.
`HD44780_ROM` must point at MAME's `hd44780_a00.bin`.

| Run | Result (2026-11-23) |
|---|---|
| C1: 120 seeds × 25,000 instructions, no special registers | identical |
| C2: 160 seeds × 25,000 instructions with special registers, interrupt handlers on every vector, SKIT/SKNIT, HLT | identical; 309,527 interrupt entries |
| Opcode forms executed | 1,064 of 1,110 |

Not covered by the random tests: STOP, and opcodes that write PA, PC, MA, MC, MCC or modify
SMH. On the CZ-101 those drive the LCD, power-down and the serial clock; the firmware runs
(C2b, C4) cover them. External SCK (serial mode 3), INT1/NMI edges and RxD are driven by the
board and are checked with MIDI in C4.

`CZ_TRACE_AD=1` adds A/D, timer and serial state lines to both traces for debugging.
